# Fixed English and Chinese editions

The project publishes two independent static sites. Each has all ten complete books. Chinese uses `dist/`; English uses `dist-en/`. GitHub Pages uses `dist-github/`, with Chinese at the root and English under `/en/`. There is no runtime language detection, translation service, or model API.

## Authored source

Chinese canonical files keep their existing paths. Each English book has a directory under `packages/content/translations/en/`; `registry.json` lists edition identifiers and complete manuscript filenames.

- `manifest.json` records the canonical version, source SHA-256, ordered field paths, original strings, AI authorship, and `humanReviewed: false`.
- Mathematics uses one authored field per line in `book.txt`, `supplements.txt`, and lesson `.txt` files. Programming uses JSON arrays so code indentation and newlines remain exact.
- Formula-only answers with Chinese punctuation are declared fields too. Normalize prose punctuation while preserving the mathematical fragments.
- `build-english-content.mjs` rejects stale source hashes, incomplete fields, untranslated Chinese, and changed inline mathematics. Prose inside TeX `text` labels may differ; the surrounding mathematics must remain identical.
- Materialized `.generated.json` files are static content. Programming `resolved/` files also supply fixed English data to the shared book interface.
- English programming projects have their own complete source and tests. Python replays are regenerated by actual CPython execution from English code, never by replacing strings inside Chinese trace states. Project ZIP, source viewer, and manuscript appendix use identical files.

Check meaning as well as symbols: hypotheses, quantifiers, domains, orientation, approximation versus equality, units, and signed quantities. Matching formulas cannot verify the surrounding explanation or prove correctness.

Edit authored translations and rebuild rather than editing generated books alone. When canonical content changes, review the affected fields and update their snapshot and checksum together. Stable IDs, graph edges, numeric answers, and diagram parameters remain aligned.

## Site implementation

Vite fixes the edition at build time. The English build resolves the English content index and programming assets before module loading, so Chinese book bodies are not a runtime fallback. Query parameters and saved language preferences cannot change either site's edition. The header links to the separate site and preserves the complete lesson hash.

Presentation translations live under `apps/web/src/i18n/`. Translate visible text and accessible labels only. Internal identifiers, conditions, model keys, numeric values, event handlers, and records retain their meaning. Authored exact strings and dynamic formatters are a presentation catalog, not a machine translator. Model formulas with `String.raw` must be extracted as raw runtime strings, not cooked JavaScript template text.

Local records belong to an origin. The two Pages paths share an origin; separate native hosts do not synchronize records. Do not promise account-based synchronization.

## Complete publication

Every edition includes all explanations, theorem conditions, derivations, examples, hints, solutions, conceptual checks, visual predictions, presets and observations, reviews, assessment, glossary, appendices, and source-use notes. Programming also includes all scenario feedback, task briefs, project milestones, executable source, and run instructions.

`build-english-book.mjs` generates the eight mathematics manuscripts and local-font print editions. `build-english-programming.mjs` generates both programming manuscripts, print editions, and the English search index. `build-language-sites.mjs` stages downloads by language and builds both sites plus the Pages artifact.
